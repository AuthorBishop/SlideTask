# SlideTask 增长与商业方案 v1

> 决策已确认：主战场国内 / 第一阶段唯一主指标 D7 留存 > 25% / 月预算 5k-2w / 产品改造范围 P0+P1。

## Problem Statement

如何让从未听说过 SlideTask 的人，在被一条 60 秒视频里"滑条推进任务"的手感打动后完成下载，并在第 7 天仍然每天滑一次？

把原始想法"联系博主拍视频"从**渠道**升级为**策略**：博主是渠道，"视频里那 5 秒的镜头"才是产品。

## 产品现状盘点（基于代码库事实）

- 纯本地优先：`expo-sqlite`（Native）+ IndexedDB（Web），**无账号、无同步、无付费、无分享、无埋点**
- 页面结构：单 tab 首页 + 设置 + 已完成 + 任务详情 + 今日焦点抽取
- 已有能力：滑条式节点进度、节点内联编辑、专注模式、任务配色随机分配、音效 + 触觉反馈、字体分级、确认弹窗、移除任务
- `(auth)` 目录存在但账号体系未落地

### 核心资产（差异化）

把任务做成**可滑的流程条**：拖把手推过节点 + "咔哒"音效 + 触觉反馈 + 滑到底的完成仪式。三个传播属性：

1. 一眼看懂，0 解说也能理解
2. 手感可听（ASMR 属性，短视频天然吃这个）
3. 结果可视（完成瞬间有仪式感，适合做截图/分享卡）

### 三个致命风险

1. **成功指标无法测量** — 无埋点、无账号，用户第 2 天没打开你根本不知道。D7 留存这个主指标当前不可观测。
2. **流量漏斗是漏的** — 无归因，博主带来的下载无法追踪来源，无法判断复投谁。
3. **无账号 = 无 LTV** — 换机/卸载即失联，投流回收模型算不过来。

## Recommended Direction

**「流程型待办 + 垂直模板承接 + 7 天挑战钩子 + 可归因的博主矩阵」。**

不做泛待办（红海、无故事），定位为"一个任务 = 一条可滑的流程条"，切入备考 / 项目推进 / 健身这类**天然是流程**的场景，用可导入的模板作为视频转化落点（"视频里这个 60 天计划，口令码直接导入"）。

所有博主内容统一挂「7 天流程挑战」钩子，避免一次性流量蒸发；每位博主独立口令码归因，用**留存用户 CAC**（不是播放量、不是下载量）做淘汰与复投。

### 商业判断（诚实版）

国内效率工具典型数据：付费率 1-5%，买断 18-68 元 → **单用户 LTV 约 0.3-3 元**；而博主投放的**留存用户 CAC 大概率 15-50 元**。

**结论：在当前无账号 + 买断模型下，买博主视频做增长算不过账。**

因此重新定位三件事：

1. 第一阶段的博主预算是**学习成本**，不是 ROI 投入 — 目标是快速买来样本，验证留存与付费意愿。
2. 长期增长引擎必须是**零边际成本**的：自己日更内容 + 产品内生的分享素材（用户每滑一步自动产出可分享内容）。博主只做背书和加速器。
3. 商业闭环依赖留存达标后的**账号化 + 订阅**（同步 / 模板 / 统计），否则 LTV 永远撑不住 CAC。

## 阶段路线（月 5 千 - 2 万）

| 阶段 | 产品 | 分发 | 预算 | 目标 |
|---|---|---|---|---|
| 第 1 月 | P0 归因打点 + P1 模板/引导/提醒 | 自更 30 条（跑通 5 秒爆款镜头）+ 3-5 个小博主试水 | 0-3k | 第一份 by-渠道留存数据 + D7 基线 |
| 第 2 月 | 按数据迭代首日引导（A/B） | 10-15 位中尾部（小红书 300-800/条、B站测评 2-5k、抖音尾部 0.5-2k） | 5k-1w | 按留存用户 CAC 淘汰，锁定 3-5 位可复投 |
| 第 3 月 | P2 分享素材 + 7 天总结卡 | 复投 + 1 位腰部深度测评 | 1w-2w | **D7 > 25%** + 拿到付费意愿数据 |

**投放纪律**：每个渠道累计满 100 下载才做一次决策；只看留存用户 CAC。

## Key Assumptions to Validate

- [ ] **滑条"手感"足以构成留存理由**（音效 + 触觉 + 完成仪式）→ D7 留存数据 + 首日引导 A/B
- [ ] **垂直模板人群留存显著高于泛人群** → 模板渠道 vs 泛内容渠道 D7 对比
- [ ] **D7 > 25% 在"纯本地 + 无账号"下可达** → 通知是唯一召回手段，需尽早验证
- [ ] **存在可接受付费意愿**（>2% 转化，客单 >30 元）→ 留存达标后再做付费墙测试
- [ ] **留存用户 CAC 可压到 15 元以内** → 靠自造内容与 UGC 分享卡把边际成本趋近 0

## 实施清单（范围：P0 + P1）

### P0 — 可测量（约 1 周，不做完不能投博主）

| # | 任务 | 验收标准 |
|---|---|---|
| P0-1 | 匿名 ID 生成与持久化（首次启动生成 UUID，存 SQLite/AsyncStorage） | 卸载前 ID 稳定，重装生成新 ID |
| P0-2 | 渠道口令码归因：设置页/首启输入口令 → 本地持久化渠道字段 | 输入 `SLIDE-A` 后，后续所有事件带上 `channel=A` |
| P0-3 | 埋点上报：事件批量、离线缓存、失败重试、可关闭 | 断网不丢事件，恢复后补传 |
| P0-4 | 分析后端选型与最小看板 | 能看到 by-channel 的 D1/D3/D7 留存表 |

**埋点事件定义：**

| 事件 | 字段 | 用途 |
|---|---|---|
| `first_open` | anon_id, channel, platform, ts | 安装量、渠道分布、留存分母 |
| `app_active` | anon_id, day_index | D1/D3/D7 留存分子 |
| `node_crossed` | anon_id, ts | 核心动作频次 |
| `task_completed` | anon_id, ts | 完成仪式触发 |
| `template_imported` | anon_id, template_id | 模板渠道效果 |
| `channel_set` | anon_id, code | 归因生效确认 |

**留存口径**：D7 = 安装后第 7 个自然日存在 `app_active` 事件。

### P1 — 可留存（约 1 周）

| # | 任务 | 验收标准 |
|---|---|---|
| P1-1 | 模板数据结构 + 3 个垂直模板（考研 60 天 / 项目推进 / 健身计划） | 一键导入生成完整任务 + 节点 |
| P1-2 | 首日引导：选模板 → 建任务 → 当天滑到至少一个节点完成 | 新用户首日完成率 > 60% |
| P1-3 | 本地通知（`expo-notifications`）：节点提醒 + 每日提醒 | 授权率、提醒打开率可统计 |
| P1-4 | 空态与首次启动体验改造（先给模板，而不是空白列表） | 新用户首屏不再是空列表 |

## 技术选型（待定，动手前需定）

匿名留存打点必须有服务端接收，三选一：

1. **Cloudflare Worker + D1/KV** — 几十行代码，免费额度足够，数据自有，成本 0（推荐）
2. **自托管 Umami / PostHog** — 开箱即用的看板，但国内访问速度不稳定
3. **国内 SDK（友盟等）** — 接入快，但数据合规与导出受限

倾向方案 1：数据自有、成本 0、可自定义留存看板，且与"纯本地优先"的产品气质一致。

## Not Doing（and Why）

- **不做海外市场** — 先在国内跑通脚本与转化模型，平台与语言成本可复用后再复制
- **不做社交 / 多人协作** — 需要账号体系与内容审核，短期投入产出比最差
- **不做 B 端机构渠道** — 销售周期长，与"验证留存"的当前目标不同频
- **不做功能堆叠**（日历、看板、标签、优先级）— 待办红海里功能没有胜算，交互形态才是差异化
- **现在就收费** — 会污染留存数据，且当前 LTV 撑不住 CAC
- **不按播放量 / 下载量选博主** — 只看留存用户 CAC，否则预算被"看着很火但留不住"的流量吃掉
- **不做账号同步（本阶段）** — 等留存达标后再启动，避免分散精力
